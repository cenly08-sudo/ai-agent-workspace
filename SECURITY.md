# Security Policy

## Reporting a vulnerability

Please do not open a public issue for a suspected security vulnerability or an exposed credential.

Contact the repository maintainers privately through the GitHub repository's security contact or maintainer contact listed on the project page. Include a short description, affected file or workflow, reproduction steps that do not contain real account data, and the potential impact.

Immediately revoke any credential or browser session that may have been exposed. Do not attach cookie files, storage-state JSON, private keys, or account exports to a report.

## Scope

Security reports are especially useful for credential exposure, unsafe local-file handling, path traversal, unintended remote access, and authentication-state leakage.
